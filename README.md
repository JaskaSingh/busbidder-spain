# BusBidder Spain

A command-line application that filters and ranks bus offers from five
simulated companies according to an individual traveller's requirements
and preferences, explains the first-ranked offer and lets the traveller
make a simulated booking. Final project for ACIT4420 Problem Solving with
Scripting, OsloMet, autumn 2026.

## Requirements

- Python 3.12 (developed and tested with Python 3.12.4)
- Standard library only. No packages need to be installed (see `requirements.txt`).

## Running

All commands are run from the repository root. The entry point is the
`busbidder` package:

    python3 -m busbidder COMMAND [options]

| Command | What it does |
|---|---|
| `python3 -m busbidder rank --profile budget` | Shows the profile, removed offers with reasons, the ranking with criterion scores and an explanation of the first-ranked offer |
| `python3 -m busbidder rank --profile budget --strategy minmax` | The same with min-max normalisation instead of the default anchored scores |
| `python3 -m busbidder compare --profiles budget business flexible` | Top offers for several profiles and how many different winners they give |
| `python3 -m busbidder book --profile business` | Shows the ranking, then asks for an offer, number of seats and confirmation, and saves the booking |
| `python3 -m busbidder validate` | Checks the offer file and lists every rejected, reviewed and corrected row |
| `python3 -m busbidder experiments --output results` | Runs experiments E1 to E6 and writes their tables to `results/` |
| `python3 -m busbidder --help` | Lists all commands and options |

Available profiles are `budget`, `business` and `flexible` (defined in
`config/profiles.json`). Available strategies are `anchored` (default) and
`minmax`.

Global options go **before** the command name, for example:

    python3 -m busbidder --offers data/offers_invalid.csv validate

| Option | Default | Meaning |
|---|---|---|
| `--data-dir` | `data` | Folder with `companies.csv`, `destinations.csv` and `offers.csv` |
| `--offers` | `DATA_DIR/offers.csv` | Use a different offer file |
| `--profiles-file` | `config/profiles.json` | Traveller profiles |
| `--bookings` | `state/bookings.json` | Booking file |
| `--log-dir` | `logs` | Folder for `busbidder.log` |

Exit codes: 0 success, 1 expected error (missing file, invalid profile,
unknown name), 2 invalid command-line arguments.

## Input files

| File | Content |
|---|---|
| `data/companies.csv` | The five companies: ID, name and profile description |
| `data/destinations.csv` | The fifteen destinations with road distance from Madrid and whether they are coastal |
| `data/offers.csv` | 527 generated offers covering all 75 company and destination combinations |
| `data/offers_invalid.csv` | 21 hand-written rows, each testing one validation rule |
| `config/profiles.json` | Three traveller profiles with hard constraints and weights |

`data/offers.csv` is generated by `tools/generate_data.py` with a fixed
seed. To regenerate it (the result is identical every time):

    python3 tools/generate_data.py

## Output and state

| Path | Content | In git |
|---|---|---|
| `results/` | CSV tables and text summaries from the experiments, used in the report | yes |
| `state/bookings.json` | Bookings made with `book` | no |
| `logs/busbidder.log` | Loads, rejected and reviewed rows, corrections, bookings and errors | no |

The offer files are never changed by the program. Seats left on an offer are
its original seats minus the seats booked in `state/bookings.json`. To start
again with no bookings, delete the `state` folder. The experiments never use
the real booking file, so existing bookings do not change the results.

## Tests

From the repository root:

    python3 -m unittest

Run one test file with, for example:

    python3 -m unittest tests.test_integration -v

The suite has 200 tests in `tests/`, covering normal use, invalid input,
missing data, boundary cases and a full pipeline test on the small dataset
in `tests/fixtures/pipeline/`. Tests write only to temporary folders.

## Reproducing the report's results

    python3 tools/generate_data.py
    python3 -m unittest
    python3 -m busbidder experiments --output results

The files in `results/` should then be identical to the committed ones.

## Project structure

    busbidder/
        __main__.py       entry point for python3 -m busbidder
        cli.py            command-line commands and error handling
        errors.py         exception hierarchy
        validation.py     Bounded descriptor, text conversion, identifier checks
        models.py         Company, Destination, FareConditions, Offer
        loading.py        reading files into accepted, rejected and review
        profiles.py       traveller profiles and weight checks
        filtering.py      hard constraint classes
        registry.py       reusable name registry used by the decorators
        criteria.py       scoring criteria registered with @criterion
        scoring.py        normalisation strategies and weighted ranking
        explain.py        generated explanation of the first-ranked offer
        booking.py        booking references, booking file and seat reservation
        reporting.py      text tables and summaries
        experiments.py    experiments E1 to E6
        logging_setup.py  log file configuration
    config/               traveller profiles
    data/                 input data
    tools/                data generator
    tests/                unit and integration tests
    results/              experiment output
